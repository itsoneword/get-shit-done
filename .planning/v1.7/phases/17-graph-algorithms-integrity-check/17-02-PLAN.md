## Check 10 implementation

Add `const graph = require('./graph.cjs');` to `verify.cjs`'s existing top-of-file require block (alongside `frontmatter.cjs`, `state.cjs`, `install-transform.cjs` — no naming collisions with any existing identifier in the file).

Insert this block into `cmdValidateHealth`, after the existing `// ─── Check 9: Source↔Runtime symmetry ───` block's closing `}` and before `// ─── Perform repairs if requested ───`:

```js
// ─── Check 10: Graph integrity (structural cycles/dangling = error; advisory dangling/contradictions = info) ───
{
  const graphModel = graph.buildGraph(cwd);
  const integrity = graph.computeGraphIntegrity(graphModel);

  for (const cycle of integrity.cycles) {
    addIssue(
      'error',
      'E-GRAPH-CYCLE',
      `Dependency cycle: ${cycle.nodes.join(' -> ')}`,
      'Break the cycle in ROADMAP.md phase "Depends on" prose or PLAN frontmatter depends_on; not auto-repairable',
      false
    );
  }

  for (const e of integrity.danglingStructural) {
    addIssue(
      'error',
      'E-GRAPH-DANGLING',
      `Dangling ${e.type} edge (${e.source}): ${e.from} -> ${e.to}`,
      'Fix or remove the reference; not auto-repairable (author-supplied data)',
      false
    );
  }

  for (const e of integrity.danglingAdvisory) {
    addIssue(
      'info',
      'I-GRAPH-DANGLING',
      `Dangling ${e.type} edge (${e.source}): ${e.from} -> ${e.to}`,
      'Advisory only — review with `gsd-tools graph validate`',
      false
    );
  }

  for (const c of integrity.contradictions) {
    addIssue(
      'info',
      'I-GRAPH-CONTRADICTION',
      c.message,
      'Advisory only — review with `gsd-tools graph validate`',
      false
    );
  }
}
```

No entry is pushed to the `repairs` array for any of these findings (unlike, e.g., `E004`/`E005` which push `'regenerateState'`/`'resetConfig'`) — this satisfies GRAPH-06's "not `--repair`-able" constraint structurally: there is no `case` in the repair `switch` for any graph finding, so `--repair` simply has nothing to do with them, and `repairable: false` on every `addIssue` call above keeps `repairable_count` accurate.
