Use `parseMustHavesBlock(content, 'key_links')` from `frontmatter.cjs` to extract the raw items (already handles both plain-string and `{key: value}` object items per its existing dynamic-indent parser — DO NOT re-parse the YAML yourself, call this function).

Real items come in TWO shapes:
1. Structured: `{ from: "path/a.cjs", to: "path/b.cjs" }` (parseMustHavesBlock returns this as a plain object with `from`/`to` keys already).
2. Free-text arrow string: `"step X grep for Y -> Z check (broken = ...)"` (parseMustHavesBlock returns this as a plain string — this is the MAJORITY shape in this repo's real PLAN.md files).

Add a new pure exported function:
```js
function parseKeyLinkItem(item) {
  if (item && typeof item === 'object' && item.from && item.to) {
    return { from: String(item.from).trim(), to: String(item.to).trim() };
  }
  if (typeof item === 'string') {
    const parts = item.split(/->|→/);
    if (parts.length >= 2) {
      const from = parts[0].trim().replace(/^["'`]|["'`]$/g, '');
      let to = parts.slice(1).join('->').trim();
      to = to.replace(/\s*\([^)]*\)\s*$/, ''); // strip trailing "(broken = ...)" parenthetical
      to = to.replace(/^["'`]|["'`]$/g, '').replace(/["'`]$/g, '');
      return { from, to };
    }
  }
  return null;
}
```

For each item, `const link = parseKeyLinkItem(item)`; if non-null, add artifact nodes `{id: 'artifact:' + link.from, type: 'artifact'}` and `{id: 'artifact:' + link.to, type: 'artifact'}`, then edge `{ from: 'artifact:' + link.from, to: 'artifact:' + link.to, type: 'wires', source: 'plan_key_links' }`. Items with no `->`/`→` and no `{from,to}` shape are skipped (no edge).

## ASSUMPTIONS

Discretionary decisions made during planning (all within 16-CONTEXT.md's "Claude's Discretion" grant — none override a LOCKED decision):

1. **Milestone scope**: `buildGraph(cwd)` scopes to the CURRENT milestone only (via `extractCurrentMilestone` for ROADMAP.md and `phasesDir(cwd)` for phase dirs), matching how `roadmap.cjs` itself already scopes. Archived-milestone phases are out of scope for Phase 16's graph; a future phase can extend `buildGraph` with an `{ includeArchived: true }` option if needed.
2. **Node shape stays minimal**: nodes are strictly `{id, type}` — no descriptive metadata (e.g. no `wave` field on plan nodes, no `provides` text on plan nodes). Keeps dedup/equality/testing trivial. Phase 17+ can widen the node shape if an algorithm needs more.
3. **SUMMARY `provides` (free text) is not an edge**: only `requires` (→ `provides` edge, reversed direction) and `affects` (→ `affects` edge) produce graph edges from SUMMARY frontmatter, per the LOCKED edge-mapping table. The top-level `provides:` list remains descriptive-only in Phase 16.
4. **`related_to` maps to edge type `depends_on`**, distinguished from `depends_on` only by `source: 'todo_related_to'` vs `'todo_depends_on'` — the LOCKED edge-type enum (`depends_on|provides|affects|satisfies|wires`) has no separate "relates_to" type.
5. **Unresolvable free-text references are skipped, not fabricated**: when a `requires`/`affects`/`depends_on`/`related_to`/`key_links` item contains no phase/plan/todo-id-shaped token (e.g. `"add-backlog"`, `"future agentic phases"`, `"no arrow here"`), no edge is created for that item. This differs from the LOCKED "retain dangling edges, don't silently drop" rule — that rule applies to edges whose target node id IS constructible but doesn't resolve to an existing node (Phase 17's job to flag). Here, no node id can even be constructed from free prose, so there is nothing to retain.
6. **CLI ignores `--raw`**: `graph analyze` is already the human-readable form and `graph export` is already the machine-readable form: neither branches on the global `--raw` flag (unlike commands that toggle between JSON and a short raw string).
