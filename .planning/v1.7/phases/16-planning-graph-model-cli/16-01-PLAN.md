### refToNodeId(str) — phase/plan reference resolver
Resolves a free-form string that MAY start with a phase or plan reference into a node id, or `null` if unresolvable. Used for `Phase N` prose and bare `NN-NN`/`NN-NN-slug` forms (Plan 16-02 reuses this for SUMMARY requires/affects and the REQUIREMENTS.md traceability table).
```js
function refToNodeId(str) {
  if (typeof str !== 'string') return null;
  const m = str.trim().match(/^(?:Phase\s+)?(\d+[A-Z]?(?:\.\d+)*)(?:-(\d{2}))?/i);
  if (!m) return null;
  return m[2] ? `plan:${m[1]}-${m[2]}` : `phase:${m[1]}`;
}
```
Test cases (must pass): `refToNodeId("Phase 16")` → `"phase:16"`; `refToNodeId("05-01")` → `"plan:05-01"`; `refToNodeId("07-05-parallel-safety-gate")` → `"plan:07-05"`; `refToNodeId("existing")` → `null`; `refToNodeId("add-backlog")` → `null`; `refToNodeId("future agentic phases")` → `null`.

### resolvePlanDepRef(item, currentPhaseNum) — PLAN depends_on resolver
PLAN frontmatter `depends_on` arrays contain EITHER a cross-phase `"NN-NN"` string OR a bare same-phase `"NN"` string (real example: `.planning/v1.5/phases/04-agent-observability-telemetry/04-02-PLAN.md` has `depends_on: [01]`, meaning "this phase's own plan 01", i.e. `plan:04-01`).
```js
function resolvePlanDepRef(item, currentPhaseNum) {
  if (typeof item !== 'string' && typeof item !== 'number') return null;
  const s = String(item).trim();
  const full = s.match(/^(\d+[A-Z]?(?:\.\d+)*)-(\d+)$/);
  if (full) return `plan:${full[1]}-${full[2].padStart(2, '0')}`;
  const bare = s.match(/^(\d+)$/);
  if (bare) return `plan:${currentPhaseNum}-${bare[1].padStart(2, '0')}`;
  return null;
}
```
Test cases: `resolvePlanDepRef("05-01", "05")` → `"plan:05-01"`; `resolvePlanDepRef("01", "04")` → `"plan:04-01"`; `resolvePlanDepRef(1, "04")` → `"plan:04-01"` (numeric frontmatter values are legal YAML, extractFrontmatter may hand back a string already — handle both).

### Node/edge dedup + determinism (apply now, both plans reuse)
- Nodes: keyed by `id` in a `Map`; if an id is added twice, keep the first (no error, no re-add).

- Final output arrays are SORTED for determinism: `nodes` ascending by `id` (plain string `<`); `edges` ascending by `from`, then `to`, then `type`, then `source`.
