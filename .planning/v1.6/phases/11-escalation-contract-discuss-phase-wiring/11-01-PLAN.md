Create `get-shit-done/references/escalation-contract.md` — a self-contained framework reference doc (embed tier definitions; do not reference REQUIREMENTS.md — discretion exercised for self-containment, matching resolution-loop.md). Structure and content:

**`## Purpose`** — single paragraph: this contract makes autonomous-run escalation deterministic. The evaluator applies it as a MEMBERSHIP CHECK against literal condition lists, not as heuristic judgment — prose criteria drift across LLM runs; lists do not.

**`## Verdict Tiers`** — three tiers with exact semantics:
- `proceed` — confidence HIGH AND no criterion condition met. Execute; ledger records it. `escalated: false`
- `proceed-and-log` — confidence MEDIUM AND no criterion condition met. Execute; flagged for morning review. `escalated: false`
- `park-and-ask` — ANY criterion condition met, regardless of confidence. Do not execute the decision autonomously. `escalated: true`
State explicitly: `escalated` is true if and only if the verdict is `park-and-ask`.

**`## Criteria`** — four subsections, each with the structure: criterion name → discrete condition list → mapped tier (`park-and-ask` for all four). Use these literal condition lists verbatim (refine wording only, never weaken to prose principles):

`### 1. Irreversibility` — fires when the decision proposes an action that:
1. Deletes or overwrites files not tracked by git (no `git revert` recovery path)
2. Runs destructive git operations: `push --force` to a shared remote, `branch -D` on an unmerged branch, `reset --hard` discarding uncommitted work, history rewrites (`filter-branch` / `filter-repo`)
3. Publishes or releases an artifact: `npm publish`, pushing a git tag to a remote, creating a GitHub release
4. Sends external side-effecting communication: creating issues/PRs/comments on a remote, firing webhooks, sending email
5. Applies a database schema migration or data mutation without a tested rollback
6. Rotates, revokes, or deletes credentials or keys

`### 2. Security boundary` — fires when the decision proposes an action that:
1. Reads or writes credential material: `.env*` files, token files, keychains, secrets embedded in config
2. Adds or changes network egress: a new external endpoint, a newly fetched domain, a telemetry destination
3. Modifies hook execution paths: `hooks/`, `hooks/dist/`, hook registrations in `settings.json`
4. Changes permission posture: `settings.json` permissions, `bypassPermissions`, sandbox configuration
5. Introduces code that executes untrusted or interpolated input (`eval`, `child_process` with unsanitized interpolation)

`### 3. Scope change` — fires when the decision proposes:
1. Work touching files or components outside the phase CONTEXT.md `<domain>` boundary
2. Implementing anything listed in the phase CONTEXT.md `<deferred>` section
3. Adding a dependency (npm package, external service) not named in the phase CONTEXT.md or RESEARCH.md
4. Editing REQUIREMENTS.md or ROADMAP.md scope mid-phase

`### 4. Spec ambiguity` — fires when:
1. The resolved decision contradicts a decision tagged `[STRONG]` (any variant: `[STRONG]`, `[STRONG, user-override]`, `[STRONG, specialist-backed]`) in the phase CONTEXT.md
2. The resolution loop returned LOW confidence after exhausting its budget
3. Two canonical references give conflicting directives and neither is marked superseded

**`## Tie-break Rules`** — define "borderline" operationally: the evaluator cannot determine from available facts whether a listed condition is met (the action resembles a condition but does not literally match it). Rules:
- Default: borderline → `proceed-and-log` (the neutral tier: do the work, flag it, discuss in morning review)
- EXCEPTION: borderline on irreversibility or security → `park-and-ask` (a wrong scope/ambiguity call is reviewable and revertable from the ledger later; a wrong security/irreversible call is not)

**`## How the Evaluator Applies This Contract`** — short section: read each criterion's condition list, check the decision against each condition as a membership test, record which condition (by criterion + number) fired in `escalation_reason`. If no condition fires, the verdict is determined by confidence alone (HIGH → proceed, MEDIUM → proceed-and-log).

**`## Calibration Posture`** — short note: the tie-break defaults and the trust-ladder thresholds (zero hard-criteria misses; ≤1 soft miss landing in plain proceed; ≤3/10 false parks) are dials, not doctrine — a neutral starting point expected to be tuned after the first real overnight runs. Calibration procedure and gate live in `.planning/v1.6/phases/11-escalation-contract-discuss-phase-wiring/11-CALIBRATION.md`.
