## Decision record schema (DECISIONS.jsonl, one JSON object per line)

Required at write time (reject with exit 1 + clear stderr if any missing):
- `decision`     — string, the decision made
- `alternatives` — array, options considered
- `evidence`     — string/array, why this decision
- `confidence`   — string, e.g. STRONG/MEDIUM/WEAK
- `escalated`    — boolean OR null (field MUST be present; null allowed only when no evaluator ran)

Auto-filled by the CLI (overwrite any caller-supplied value):
- `id` — `dec-NNN` (3-digit zero-padded, monotonic per run)
- `ts` — `new Date().toISOString()`

Caller-supplied optional context (default to null if absent):
- `phase`, `context`, `question`
- `escalation_verdict`, `escalation_reason` (Phase 11 populates; null in Phase 10)

## Path layout (run-scoped, NOT global)
`.planning/run/<run-id>/DECISIONS.jsonl`
`.planning/run/<run-id>/MAILBOX.jsonl`
`.planning/run/<run-id>/RUN-META.json`
`.planning/run/<run-id>/parked/`           (created at init, unused in Phase 10)

## Run-context gate (LEDGER-03)
effectiveRunId = explicit run-id arg || process.env.GSD_RUN_ID
- if no effectiveRunId → stderr message naming what's missing, exit 1
- if run dir does not exist → stderr "run not initialized: <id> (run: gsd-tools run init <id>)", exit 1
Interactive sessions never set GSD_RUN_ID, so they hit exit 1 (loud) — never a silent write.

## Patterns to mirror verbatim from lesson.cjs (read it via @ above)
- readLessons → readLedger: malformed-line-skipping JSONL reader (split '\n', filter blank, try/catch JSON.parse, skip on error)
- nextId → nextDecId: regex `/^dec-(\d+)$/`, max+1, padStart(3,'0'), prefix 'dec-'
- filterLessons → filterLedger: opts object, chained .filter, tail-last (default 50)
- formatTable → table formatter: column-width auto-sizing, two-space join
- cmdList raw/table split: raw=true prints one JSON.stringify(rec) per line, else formatTable

## Deviations from lesson.cjs (load-bearing — do NOT copy these from the template)
1. NO writeLedger / full-file rewrite export. The ledger is append-only — only fs.appendFileSync ever writes DECISIONS.jsonl. lesson.cjs has writeLessons for update/bump — ledger.cjs must NOT have an equivalent.
2. NO cmdUpdate / cmdBumpRecurrence / ledger patch. Superseding records (future) are a new append with a `supersedes` field, not an in-place edit.
3. Required-field validation in cmdLedgerAppend BEFORE appendFileSync (lesson.cjs has no such gate).
4. GSD_RUN_ID + run-dir-existence gate at the top of cmdLedgerAppend (lesson.cjs writes to a single global path).
5. Library functions (readLedger, filterLedger, nextDecId, ledgerPath) return data and NEVER call process.exit — only cmd* handlers do process I/O and exit.
