## Mailbox record schema (MAILBOX.jsonl, one JSON object per line)
Full schema (per CONTEXT.md / ARCHITECTURE.md sketch):
`id, ts, run_id, phase, decision_id, question, context, options, evidence, status, answer, answered_ts`

Required at write time (reject with exit 1 + clear stderr if missing): `question`
Auto-filled by the CLI (overwrite caller value):
- `id` → `q-NNN` (3-digit zero-padded, monotonic per run)
- `ts` → new Date().toISOString()
Defaulted if absent:
- `run_id` → effectiveRunId
- `status` → 'open'
- `phase, decision_id, context, options, evidence, answer, answered_ts` → null

(In Phase 10 the mailbox is write/read only — answer/answered_ts stay null; Phase 12 fills them via review.)

## Run-context gate (same as ledger, LEDGER-03 sibling)
effectiveRunId = explicit run-id arg || process.env.GSD_RUN_ID
- no effectiveRunId → stderr naming what's missing, exit 1
- run dir absent → stderr "not initialized: <id> (run: gsd-tools run init <id>)", exit 1
Interactive sessions never set GSD_RUN_ID → loud exit 1, never a silent write.

## Patterns to mirror verbatim from lesson.cjs (read it via @ above)
- readLessons → readMailbox: malformed-line-skipping JSONL reader (return [] if file absent)
- nextId → nextQId: regex /^q-(\d+)$/, prefix 'q-', padStart(3,'0')
- filterLessons → filterMailbox: opts {status, last}; if opts.status filter r.status === opts.status; tail to opts.last (default 50)
- formatTable → mailbox table: columns id, ts, phase, status, question
- cmdList raw/table split

## Deviations (load-bearing — same correctness posture as ledger.cjs)

2. NO cmdUpdate / patch.
3. Required-field validation (question) BEFORE appendFileSync.
4. GSD_RUN_ID + run-dir-existence gate at top of cmdMailboxAppend.
5. Library functions return data, never process.exit — only cmd* handlers exit.
