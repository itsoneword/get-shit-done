**`<context>` section** — Describe argument parsing:
- `$ARGUMENTS` may contain `--full`, `--subsystem <name>`, `--yes`, `--skip-docs`.
- No flags → agent infers scope from `init document` state (last-run timestamp + GSD activity since).
- Explicitly reject `--phase N` with an error: "--phase N is not supported. Use --subsystem <name> to target a specific subsystem, or --full to regenerate everything."

**`<when_to_use>` section** — Bulleted:

Use `/gsd2:document` for:
- Generating a system map for the first time on any project maturity (greenfield with code only, brownfield with full `.planning/`)
- Refreshing the map after a milestone completes (the `complete-milestone` workflow suggests this)
- Targeted update of one subsystem that is known-stale (`--subsystem <name>`)

Skip `/gsd2:document` for:
- Trivial changes (button color, typo) — milestone-level updates only
- Projects with no code AND no planning artifacts

**`<process>` section** — Numbered, high-level (detailed steps live in `workflows/document.md`):
1. Call `init document` for state (last-run timestamp, existing docs, activity since)
2. Resolve scope (`--full` / `--subsystem <name>` / inferred incremental)
3. Full → spawn parallel `gsd-document-mapper` agents per discovered subsystem; write `docs/system/*.md` + root `SYSTEM-MAP.md`
4. Incremental → spawn single `gsd-document-updater` agent in propose mode → show diff → user confirms (`--yes` auto-confirms) → agent applies
5. Append changelog entry at top of root `SYSTEM-MAP.md`
6. Commit generated docs via `gsd-tools.cjs commit` (respects `commit_docs` config)
