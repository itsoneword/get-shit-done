<objective>
Make the `plan-phase` revision loop **convergence-aware** (CONV-01). Today, when the plan checker keeps finding issues across all 3 iterations, the loop fires a blunt `Max iterations reached. {N} issues remain` message with no signal about *whether* the work was making progress. The user can't tell "1 issue left, one more retry would clear it" from "stuck at 5, retrying is pointless."

The fix: the orchestrator captures the BLOCKER+WARNING count at **every** `## ISSUES FOUND` (the checker already emits this — `**Issues:** {X} blocker(s), {Y} warning(s), {Z} info`, see `agents/gsd-plan-checker.md`) into a small **inline** trajectory list (C1, C2, C3…). At the existing iteration-3 escalation boundary it branches the diagnosis:
- **Stalled** (count never decreased across the trajectory) → emit a `## STALL DETECTED` block showing the trajectory (`Issue count: 5 → 5 → 5 — not converging`) + the unresolved issue list.
- **Converging but incomplete** (count decreased at least once but isn't zero) → keep the existing `Max iterations reached. {N} issues remain` message.

**Both branches present the SAME existing options: Force proceed / Provide guidance and retry / Abandon.** No new options, no new escalation mechanism, no new exit.

**Hard scope guardrails (from 05-CONTEXT.md, all [STRONG]):**
- Do **NOT** raise `max_iterations` (stays 3) and do **NOT** add an earlier exit. With `iteration_count` starting at 1, there are exactly 2 comparison cycles (C2-vs-C1, C3-vs-C2), so "non-decreasing for 2 consecutive cycles" is confirmable **precisely at iteration 3** — the same boundary the max-iterations branch already fires. CONV-01 makes that existing boundary convergence-aware; it does not move it.
- Stall state is **INLINE only** — orchestrator working state, NOT written to a file. (The CHECKPOINT-file pattern is a Deferred Idea for if/when planning becomes resumable mid-loop across sessions; do NOT build the file path now.)
- Do **NOT** change the checker agent's output contract — the count line already exists; the orchestrator just parses it.
- BLOCKER+WARNING only — `info` is excluded from the convergence metric.

This is workflow PROSE (Markdown instructions the orchestrator LLM executes at runtime), so the edit must read as clear runtime instructions AND be grep-checkable. There is no unit test for prose.
</objective>
