1. **Step 0 — Detect existing isolation (ALWAYS first):**
   ```bash
   GIT_DIR=$(cd "$(git rev-parse --git-dir)" && pwd -P)
   GIT_COMMON=$(cd "$(git rev-parse --git-common-dir)" && pwd -P)
   ```
   If `GIT_DIR != GIT_COMMON`: already in a linked worktree — do NOT create another.
   Submodule guard: `git rev-parse --show-superproject-working-tree 2>/dev/null`.

2. **Step 1a — Native tools first:** if a native worktree tool exists (EnterWorktree / WorktreeCreate / a `/worktree` command / a `--worktree` flag), use it instead of raw git.

3. **Step 1b — git worktree fallback (directory priority order):** 1) explicit user preference; 2) existing `.worktrees/`; 3) existing `worktrees/`; 4) existing global `~/.config/.../worktrees/$project`; 5) default `.worktrees/`.

4. **Safety — ignore check:** `git check-ignore -q .worktrees 2>/dev/null`. If NOT ignored: add it to `.gitignore`, commit, THEN proceed.

5. **Sandbox fallback:** if `git worktree add` fails with a permission error → work in place; run setup and baseline tests in place.

6. **Step 3 — Project setup:** install deps for the detected stack (`npm install` / `cargo build` / `pip install -r requirements.txt` / `poetry install` / `go mod download`).

7. **Step 4 — Baseline test verification:** run the test suite; if it fails, report and ask whether to proceed or investigate.

8. **Red flags:** never create a worktree when Step 0 detects existing isolation; never use raw `git worktree add` when a native tool exists; never skip the ignore check; never skip the baseline test.

9. **Phase 7 boundary note (mandatory):** this reference documents the technique ONLY. The execute-phase add→wave→merge orchestration and the parallel-safety gate are Phase 7 scope (its scope item 1). Do NOT extend this reference with orchestration logic or a gsd-tools helper.

The opening line should state WHEN to load this reference (e.g. "Load this when you need to isolate work in a separate working tree before running a task — detect existing isolation first.").
